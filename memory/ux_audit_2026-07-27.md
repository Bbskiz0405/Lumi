# Lumi v0.4.63 使用者體驗健檢

> 健檢日期：2026-07-27  
> 角度：一般使用者實際完成「記錄 → 確認 → 修改 → 找回 → 備份」的完整流程。  
> 範圍：首頁智慧輸入、導覽、行事曆、任務、財務、筆記、時間軸、問 Lumi、AI 財務顧問、API 設定、備份還原。

## 健檢方式與限制

- 逐頁閱讀目前 v0.4.63 的畫面流程、狀態管理、資料查詢與錯誤處理。
- 先前已確認 release APK 可在 Pixel 8a 冷啟動，舊資料庫可升級至 migration v2。
- 為避免讀取或改動手機私人資料，本次沒有用自動化工具擷取畫面內容，也沒有執行「完全取代」還原。
- 因此這是一份有程式行為證據的 UX review；觸控手感、鍵盤在各尺寸上的遮擋與真實使用者理解程度，仍應再用一組測試資料做實機走查。

---

## 總結

Lumi 現在最強的是「一個入口快速記錄」與一致的深色視覺。最大的問題不是缺少更多功能，而是：

1. **動作很快，但改錯與復原不夠快。**
2. **某些畫面會讓使用者以為資料存到眼前日期，實際可能存到另一日。**
3. **資料讀取失敗常被顯示成「沒有資料」，容易造成資料消失的恐慌。**
4. **AI 會使用哪些私人資料、送到哪裡，目前沒有在使用當下說清楚。**
5. **搜尋、日期選擇、跳回原始資料等日常高頻能力不足。**

建議先完成一版「UX 安全修補」，再開發 Lumi 觀察、Widget 或同步。

## P0：應優先修正

### 1. 切換月份後，選取日期仍停在舊月份

**使用情境**

使用者在行事曆按下一個月，畫面標題已顯示新月份，接著切到財務新增記帳。

**目前問題**

- `prevMonth`／`nextMonth` 只修改 `year` 與 `month`，沒有更新 `selectedDate`。
- 行事曆下方可能仍顯示舊日期的任務。
- 財務新增會直接使用舊的 `selectedDate`，因此可能把交易存到舊月份。

**建議**

- 換月時把選取日同步到新月份，日期超出時取該月最後一天。
- 新增記帳表單內提供可點擊的日期欄位，不只把日期寫在標題。
- 提供「今天」快捷鍵。

### 2. 高信心分類直接自動儲存，沒有 Undo

**使用情境**

使用者輸入「明天買牛奶 100」，AI 或本地規則可能判成任務，也可能判成記帳。

**目前問題**

- 高信心結果直接儲存，使用者只看到短暫提示。
- 提示消失後，若分類、日期、金額或類別錯誤，必須自己到不同模組尋找並修改。
- 多筆記帳也可能直接拆分後儲存，使用者沒有先確認每一筆。

**建議**

- 儲存後顯示 5–8 秒 Snackbar：「已存為記帳 $100」＋「復原」＋「編輯」。
- 多筆拆分一律先預覽。
- 明確顯示抽出的任務日期、記帳項目、金額與分類，而不只顯示類型。
- 明顯句子可本地先判斷；只有模糊輸入才等待 AI，降低每次輸入最多 6 秒的等待。

### 3. AI 資料傳送範圍不透明

**使用情境**

使用者按「問 Lumi」，以為 App 只在本機搜尋。

**目前問題**

- `askLumi` 會取最多 250 筆任務、記帳與筆記全文，送到選擇的 AI 供應商。
- 畫面只說「我會翻你的紀錄」，沒有明確說資料會送出裝置。
- 月度回顧與財務顧問也會把相關資料送給外部供應商。

**建議**

- 第一次使用 AI 前顯示一次清楚的資料使用說明。
- 每次回答旁顯示「使用了任務 12、記帳 31、筆記 4 筆」。
- 提供排除筆記／財務等資料類型的開關。
- 改成先在本機檢索相關資料，只送必要的 10–20 筆。
- 回答附可點擊的原始資料來源。

### 4. 讀取失敗常被顯示成空資料

**使用情境**

SQLite 暫時讀取失敗，或 migration／查詢發生例外。

**目前問題**

- 任務、行事曆、筆記與首頁模組多數只把錯誤寫到 console。
- 畫面最後可能顯示「沒有待辦」「這天沒有任務」「還沒有筆記」。
- 使用者會以為資料真的不見了。

**建議**

- 空狀態與錯誤狀態分開。
- 錯誤狀態提供「重試」。
- 保留上一份成功資料，並提示目前可能不是最新。
- 加入全域 Error Boundary 與本機錯誤紀錄。

### 5. 首頁衍生資料仍不是單一資料庫 transaction

**目前問題**

首頁會先建立 entry，再建立 task／transaction／note；失敗後靠應用層刪除補救。如果 App 在兩步之間被終止，仍可能留下不完整資料。

**建議**

把「原始輸入＋衍生資料」改成同一個 exclusive transaction，Undo 也以同一個 entry 關聯完整復原。

## 各功能實際使用問題

## 第一次開啟與導覽

### 好用的地方

- 首頁直接顯示輸入框，核心動作明確。
- 四個模組卡片能快速看到資料概況。
- 底部保留五個主要入口，學習成本不高。

### 不直覺或不方便

- 沒有簡短 onboarding，不知道可以輸入哪些句子、資料是否只存在本機、AI Key 是否必要。
- 首頁右上 `≣`、`⌕`、`≡` 三個符號沒有文字或 accessibility label，新使用者不一定知道分別是時間軸、問 Lumi、設定。
- 底部 tab 用 `[ ]`、`[v]` 等文字圖示，辨識速度低於標準圖示。
- 設定入口只在首頁；人在財務或筆記頁時要先回首頁。
- Tab 使用 `router.push`，反覆切頁可能累積導覽歷史，Android 返回鍵可能依照點擊過的 tab 往回走。
- 外層與行事曆／財務內層都支援水平滑動，可能產生巢狀手勢衝突。

### 建議

- 第一次開啟用三張以內的可跳過介紹，並提供範例輸入。
- 右上按鈕改成容易辨識的圖示並補語意標籤。
- Tab 切換使用 navigator state，不建立新的 push 歷史。
- 設定可由所有主頁面進入。

## 首頁智慧輸入

### 好用的地方

- 輸入失敗時文字會保留。
- 模糊分類可切換任務／記帳／筆記。
- 會顯示 AI 或本地判斷來源。

### 不直覺或不方便

- 送出按鈕只有 28px，低於建議的 44px 觸控範圍。
- 任務預覽沒有顯示抽到的日期；記帳分類顯示的是 `food` 等內部英文代碼。
- 分錯類後無法在確認卡直接修改標題、日期、金額與分類。
- AI Key 存在時，每次輸入都先走網路 AI，明顯輸入也要等待。
- 成功提示時間短，沒有 Undo，也沒有「查看剛才資料」。
- 最近動態只能跳到模組；記帳與筆記不能精準跳到該筆編輯畫面。

### 建議

- 改成結構化預覽卡，可直接修日期／金額／分類。
- 成功後提供 Undo 與查看。
- 先本地判斷明確句子，AI 只處理模糊輸入。
- 最近動態每一筆都能打開對應詳情。

## 任務

### 好用的地方

- 待辦與完成項目有分區。
- 到期日有今天、明天、逾期提示。
- 詳情頁可以編輯、完成與刪除。

### 不直覺或不方便

- 日期必須手打 `YYYY-MM-DD`，手機上很慢。
- 驗證只檢查格式，`2026-99-99` 也可能通過。
- 沒有「今天／明天／下週」快捷選項。
- 新增與編輯按鈕沒有送出中的鎖定，連點可能建立重複資料。
- 行事曆單日任務使用 `priority DESC` 字串排序，實際不會依「高、中、低」正確排列。
- 一般任務列表沒有依優先度整理，也沒有搜尋、標籤篩選。
- 完成切換或儲存失敗時沒有畫面錯誤與復原。
- 空狀態只說沒有任務，沒有引導「新增」或範例。

### 建議

- 使用原生日期選擇器＋相對日期快捷鍵。
- 實際驗證年月日。
- 儲存期間 disable，完成後提供短暫 Undo。
- 排序改成逾期 → 今天 → 未來 → 無日期，再依高／中／低。

## 行事曆

### 好用的地方

- 任務與財務會用不同顏色的小點提示。
- 今天與選取日期容易區分。
- 可直接為選取日期新增任務。

### 不直覺或不方便

- 換月後選取日期仍在舊月份，屬於 P0。
- 沒有顏色圖例，不知道紅／橘／藍／綠點代表什麼。
- 點到有財務綠點的日期後，行事曆頁只顯示任務；使用者可能以為綠點可展開交易。
- 沒有回到今天的快捷鍵。
- 完成任務仍留在單日列表，但月曆任務點消失，兩邊語意不一致。

### 建議

- 同步月份與選取日。
- 增加小型圖例與「今天」按鈕。
- 單日內容可同時列任務與交易，或點綠點後直接切至財務並保留日期。

## 財務

### 好用的地方

- 收入、支出、結餘一眼可見。
- 可切月／年／全部。
- 支援收入／支出、分類、編輯、刪除與計算機。

### 確認到的 Bug／不可達功能

- 從「編輯記錄」按刪除，會先出現一次確認，再呼叫另一個會再次確認的刪除流程。
- `BudgetMeter`、預算查詢與寫入服務存在，但財務畫面沒有顯示預算功能。
- 新增自訂消費分類的 state 與 handler 存在，但畫面沒有入口。

### 不直覺或不方便

- 新增記帳使用全域 `selectedDate`，切月份後可能存錯日。
- 編輯交易不能修改日期。
- 在「年／全部」視圖按 AI 顧問，分析的仍是目前月曆月份，範圍容易誤解。
- 月／年／全部畫面上方仍固定顯示單月行事曆，年與全部視圖會佔據大量空間且語意不一致。
- 摘要數字沒有 `NT$` 或貨幣單位。
- 自訂分類在圓餅圖會使用灰色與原始名稱，多個自訂分類難以區分。
- 「所有記錄」用 ScrollView 一次 render 全部，資料多時會卡。
- 重置全部資料的按鈕只有 `↻`，而且靠近 AI 與新增按鈕，意義不清楚。
- 計算機算式錯誤時，按確認沒有提示。

### 建議

- 先修錯誤日期與雙重刪除確認。
- 讓日期可在新增／編輯表單直接修改。
- 完成預算 UI 與分類管理，否則移除不可達程式避免誤判完成度。
- 年／全部視圖縮起月曆，顯示明確期間。
- 改用 FlatList 分頁。

## 筆記

### 好用的地方

- 新增與編輯都在同一個簡單 bottom sheet。
- 可自訂標籤並篩選。
- 卡片預覽與時間資訊清楚。

### 不直覺或不方便

- 編輯時把內容清空再按儲存，視窗會直接關閉且沒有說明；原筆記其實不變。
- 儲存、刪除、標籤寫入失敗大多沒有畫面提示。
- 刪除標籤靠長按，沒有任何提示，幾乎無法被發現。
- 刪除標籤後，既有筆記仍保留該分類，但篩選入口消失。
- 標籤多時會在頁面上方換行，占掉大量空間。
- 沒有搜尋、置頂或排序；筆記多之後難以找回。
- 離開編輯視窗會直接丟棄未儲存修改，沒有提醒。

### 建議

- 空內容顯示驗證錯誤，或明確詢問是否刪除。
- 加入搜尋，標籤列改水平滾動。
- 提供標籤管理頁，不依賴長按。
- 有修改未存時，取消／返回需確認。

## 時間軸與本月回顧

### 好用的地方

- 任務、財務與筆記整合成一條時間線，差異化很明確。
- 月度敘事有快取，不會每次進入都重打 AI。

### 不直覺或不方便

- 時間軸卡片不能點回原始任務、交易或筆記。
- 任務使用「建立時間」放入時間軸，不是完成時間或到期時間；使用者可能把它理解成事件發生時間。
- 完成任務不會產生完成事件，所以時間軸不是真正的活動紀錄。
- 最多只取 300 筆，沒有「載入更多」或已截斷提示。
- 只能看目前月份的敘事，不能選過去月份。
- 新增資料後，已生成的敘事不會標示「內容可能已過期」。
- 金額沒有千分位與貨幣單位。

### 建議

- 卡片可點回來源。
- 定義並顯示「建立／到期／完成」事件類型。
- 時間軸分頁並提供類型、月份篩選。
- 新資料出現時標記回顧需要更新。

## 問 Lumi 與 AI 財務顧問

### 好用的地方

- 有範例問句，降低第一次提問成本。
- 對話介面簡單，財務顧問限定資料範圍。

### 不直覺或不方便

- 問 Lumi 沒有 API Key 時，必須先送出問題才看到「未設定 API」錯誤，沒有直接引導到設定。
- AI 呼叫沒有統一 timeout／取消按鈕，網路問題時可能一直等待。
- 問 Lumi 固定使用最近 250 筆，不一定涵蓋問題需要的月份；資料多時金額答案可能不完整。
- 回答沒有來源卡片，無法快速確認 AI 是否引用正確。
- 問 Lumi、財務顧問、月度回顧各自有相似對話與設定流程，體驗不一致。
- 技術性 API 錯誤可能直接顯示給一般使用者。
- 對話離開頁面後不保留。

### 建議

- 進頁先檢查 API 狀態，沒有 Key 時顯示「前往設定」。
- 增加 timeout、取消、重試。
- 先做本機查詢與聚合，再送少量相關資料。
- 回答附日期、來源與可點擊紀錄。
- 統一三個 AI 功能的狀態、錯誤與隱私說明。

## API 設定

### 好用的地方

- 支援 Gemini、OpenRouter、OpenAI。
- Key 有安全儲存與移除確認。

### 不直覺或不方便

- 取得 Key 的網址只是文字，不能點擊。
- 儲存時不測試連線，任何字串都會顯示「已設定」，錯誤要等到之後使用 AI 才知道。
- 已設定供應商顯示內部值 `gemini`／`openrouter`，而不是一致的產品名稱。
- 說明只提到首頁分類與財務顧問，漏掉問 Lumi 與月度回顧。
- 沒有說明不同供應商可能產生費用，也沒有顯示目前模型。

### 建議

- 網址做成可點擊按鈕。
- 儲存前提供「測試連線」。
- 顯示供應商、模型、可能費用與會使用資料的功能。

## 資料與備份

### 好用的地方

- 有資料筆數、匯入預覽、合併／取代與二次確認。
- API Key 明確排除。
- 匯入錯誤會 transaction rollback。

### 不直覺或不方便

- 沒有「上次成功備份」日期，使用者不知道自己多久沒備份。
- 分享完成後沒有清楚的 App 內成功訊息。
- 隱私提示只強調 API Key 不在檔案裡，沒有提醒 JSON 仍包含完整任務、記帳與筆記，應妥善保存。
- 「合併」只依相同 ID 略過；兩份不同來源但內容相同的備份仍可能重複，畫面沒有說明。
- 沒有「刪除所有 Lumi 資料」入口；本地優先產品仍需要完整刪除權。

### 建議

- 儲存上次成功匯出時間，定期提醒備份。
- 加上「備份檔包含私人內容」提醒。
- 匯入結果顯示各類新增／略過筆數。
- 增加有多重確認的完整資料刪除功能。

## 跨頁一致性、無障礙與效能

### 無障礙

- `app` 與 `components` 目前約有 95 個 `TouchableOpacity`，只有備份頁的兩個主要按鈕設定 accessibility role／label。
- 多個按鈕只有符號，螢幕閱讀器無法說明用途。
- 許多觸控區為 28–36px，低於建議的 44px。
- 深色背景上大量使用 `#333`／`#444` 與 10–11px 小字，實機可讀性偏低。

### 鍵盤與表單

- 任務、記帳、筆記 bottom sheet 多數沒有完整的 Android KeyboardAvoiding 處理。
- 小螢幕或字體放大時，儲存按鈕可能被鍵盤遮住。
- 多數表單沒有送出中狀態與防止連點。

### 錯誤與成功回饋

- 有的地方用 Alert、有的只 console、有的顯示欄位錯誤，缺乏一致規則。
- 建議統一：
  - 欄位問題：欄位下方錯誤。
  - 暫時性錯誤：頁內錯誤＋重試。
  - 成功／可復原動作：Snackbar＋Undo。
  - 破壞性動作：確認對話框。

## 建議修正順序

### v0.4.64 — UX 安全修補

1. 換月同步 `selectedDate`，新增／編輯交易可選日期。
2. 修正記帳雙重刪除確認。
3. 任務日期做真實驗證，修正優先度排序。
4. 所有主要列表分開「空資料」與「讀取失敗」，加入重試。
5. 新增／編輯表單防連點，筆記空內容不再靜默關閉。
