# project_memory — 專案記憶系統（通用模板）

> **用法**：把本檔丟進任何專案根目錄，對 AI 說「照這個 README 建立記憶架構」即可。
> **核心原則**：AI 與人共用；**每種資訊只存一處**；「現在／過去／參考」三分。

---

## 給 AI：安裝步驟（首次見到本檔時執行）

1. 專案根目錄建立 `project_memory/`，**把本檔移入**（不是複製）成為 `project_memory/README.md`。
2. 依「縮放規則」建立骨架：**初始只建 `STATUS.md` 與 `LOG.md`**（模板見文末）。
3. 在專案的 AI 指令檔（`CLAUDE.md`／`AGENTS.md` 等，沒有就建一個 `CLAUDE.md`）加入：
   > 開工先讀 `project_memory/STATUS.md` 照「下一步」執行；每完成一個階段就 append `LOG.md` 並覆寫 `STATUS.md`；指令／路徑／踩坑查 `ENVIRONMENT.md`，不憑記憶。
4. 問使用者 1–2 個問題（專案目標？目前進度／下一步？），寫出第一版 `STATUS.md`。
5. 回報架構已建立，之後即依本檔的開工／收工流程運作。

## 檔案地圖

| 檔案 | 內容 | 更新方式 |
|---|---|---|
| `STATUS.md` | **現在**：目前階段、下一步、待辦 | 收工時**整檔覆寫** |
| `LOG.md` | **過去**：歷史紀錄歸檔 | 收工時 **append** 到結尾，不回改 |
| `ENVIRONMENT.md` | **參考**：環境、指令 SOP、介面規格、踩坑 | 有新知識隨時補（踩坑 append） |
| `plans/` | 進行中／歷史的執行計畫 | 一計畫一檔：`plan_<YYYYMMDD>_<主題>.md` |
| `README.md` | 本檔（架構說明） | 穩定不動 |

## 縮放規則（重要：不要一次建滿）

- 新專案**只建 `STATUS.md` + `LOG.md`**。
- 第一個踩坑／SOP／環境知識出現 → 才建 `ENVIRONMENT.md`。
- 第一個多日或多步驟計畫出現 → 才建 `plans/`。
- 讓架構跟著專案長大，小專案不背大架構。

## AI 開工流程（三步）

1. 讀 `STATUS.md` → 知道現在在哪、下一步做什麼。
2. 若下一步指向計畫 → 讀 `plans/` 對應計畫**全文**。
3. 需要指令／路徑／踩坑 → 查 `ENVIRONMENT.md`（**不要憑記憶打指令**）。

## AI 收工流程（兩步）

1. `LOG.md` 結尾 **append** 當次摘要（日期標題＋條列：做了什麼、結果、坑）。
2. **覆寫** `STATUS.md`（更新階段、下一步、待辦；完成的待辦直接刪——歷史在 LOG）。

> 工作時間長時不必等收工：**每完成一個階段就做一次**，防中斷失憶。

## 紀錄慣例

- LOG 條目格式：`## YYYY-MM-DD｜標題`，內文條列。
- **重要決策**在 LOG 用固定標籤 **`⭐定案：`** 記錄（含一句理由），日後可 grep 追溯。
- **實驗／量測數據必須連同量測條件一起記**；不同條件下的絕對值不可直接比較，要比就比相對量。
- 踩坑寫進 `ENVIRONMENT.md` 的踩坑清單（append-only）；LOG 只記事件經過。
- 大改動（改核心檔案、重訓、重構）前先備份到專案的 `backups/<日期>/`。

## 協作守則（內嵌，對所有 AI 生效）

1. **先溝通，再行動**：修改檔案或執行有影響的指令前，先說明計畫（改什麼、跑什麼、為什麼）。
2. **遇錯停下**：報錯不盲目重試；說明錯誤訊息、原因分析、列出多個解法讓使用者決定。
3. **不擅自切換**工具、模型、技術路線；卡關或數字反常 → 停下來問。
4. **誠實鐵律**：所有結果如實記錄與報告，不挑好看的數據、不隱藏失敗。

## 給人類的用法

- 想知道進度：看 `STATUS.md`（30 秒）。
- 想回憶某天做了啥：搜 `LOG.md`；查決策：grep `⭐定案`。
- 叫 AI 開工：「**讀 `project_memory/STATUS.md` 照下一步執行**」即可（若已照安裝步驟 3 設定，AI 會自動遵循）。

## 骨架模板（安裝時用）

### `STATUS.md` 初始內容

```markdown
# STATUS — 現在的狀態與下一步

> 唯一的「現在」。收工時直接覆寫本檔（歷史去 LOG.md）。
> 最後更新：<日期>

## 🚀 下一步（開工第一件事）

- <下一步>

## 目前階段

- <一兩行描述專案現況>

## 待辦

- [ ] <待辦>
```

### `LOG.md` 初始內容

```markdown
# LOG — 歷史紀錄歸檔（append-only，新紀錄加在檔案最下方）

> 唯一的「過去」。收工時把摘要 append 到本檔結尾，並覆寫 STATUS.md。

---
```

### `ENVIRONMENT.md`（需要時才建）

```markdown
# ENVIRONMENT — 環境、指令、規範、踩坑（單一事實來源）

> 唯一的「參考資料」檔。其他檔案需要時引用本檔，不要複製內容。

## 環境

## 常用指令 SOP

## 踩坑清單（append-only，新坑加最下面）
```
